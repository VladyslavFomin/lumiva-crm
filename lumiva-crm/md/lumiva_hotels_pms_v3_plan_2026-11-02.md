# PMS v3 — план после сравнения с Veboni / Elektraweb / Luwi (2026-11-02)

Порядок утверждён владельцем 2026-11-02. Ядро PMS (брони, группы, партнёры, шахматка, уборка, касса/смены,
ночной аудит, KBS, прайс сезона, тарифы, акции, Channex, онлайн-регистрация, точки продаж, рекомендации цены,
отзывы) уже есть — здесь только недостающее.

## Этап A — обязательное

1. **e-Fatura / e-Arşiv** — счёт гостю/агентству электронным документом через интегратора (GİB).
   Налог на проживание (konaklama vergisi) уже считается. Нужен выбор интегратора владельцем.
2. **Онлайн-предоплата брони** — ссылка на оплату (iyzico / PayTR / ЮKassa уже есть в CRM, к отелям не
   подключены), оплата при бронировании на сайте, платёж в фолио, возврат.
3. **Сценарии сообщений гостю** до заезда → во время → после: поверх QR номера (Guest Care) и WhatsApp.
   Приветствие в день заезда, опрос в середине проживания, после выезда — просьба об отзыве (довольных →
   Google/Booking, недовольных → менеджеру), автоперевод, отчёт по скорости ответа.

## Этап B — второй эшелон

4. Выгрузка проводок в бухгалтерию (Logo / Mikro), единая кассовая книга отеля.
5. Склад и закупки F&B: рецептуры, списание по чекам точек продаж, остатки, закупки.
6. Программа лояльности на профилях гостей.
7. SPA в счёт номера (запись из модуля бронирований → строка фолио).
8. Мобильное приложение — `md/mobile-app-backlog.md`.

## Этап C

1. **Сеть отелей** — сводные отчёты по всем объектам, единые шаблоны (тарифы, акции, услуги, письма).
2. **Замки и киоск**:
   - Карточные замки отелей (VingCard / Salto / Onity) — только через вендора, по запросу клиента.
   - Свои силы: замки с открытым облачным API (напр. TTLock) — PIN-код на даты проживания при заселении,
     отправка гостю в WhatsApp, сгорает при выезде.
   - Киоск самозаселения `/kiosk` на iPad (Guided Access): поиск брони, фото паспорта (MRZ уже есть),
     данные гостей, подпись, оплата остатка по QR, KBS, заселение; ключ — ресепшен или PIN замка.
     Основа — онлайн-регистрация `/c/:token`.

## Этап B — решения владельца 2026-11-02

- **Лояльность** — делается: область программы на выбор (отели / бренды-сеть / весь аккаунт, отель — в одной
  программе), уровни + баллы + простой режим скидки, взаиморасчёты сети (возмещение < 100 %, месячный лимит приёма
  на отель, блэкаут, перенос мелких переводов, флаг перекоса), сообщения — через Автоматизации.
- **Склад и закупки F&B — ОТЛОЖЕНО владельцем** (2026-11-02). Ответы владельца на будущее: согласование заказов —
  на выбор клиента (сам закупщик или через управляющего); нужен центральный склад сети. Набросок модели: общий
  справочник продуктов на аккаунт; склады — центральный (без отеля) / главный отеля / склад точки продаж (списание
  чеков) / мини-бар; остаток и средневзвешенная себестоимость на складе, валюта склада; заказ поставщику (черновик →
  согласование → утверждён → приёмка, частичная), перемещения, списания, инвентаризация; рецептуры на позиции точек
  продаж (чек списывает, сторно возвращает); отчёты — остатки/минимум (событие в Автоматизации), фудкост по точкам,
  себестоимость «всё включено» на гостя-ночь.
