# Отели: что ещё нужно до уровня PMS — план (2026-10-25)

Источник: просмотр кода модуля `backend/src/hotels` + живых данных ATG HOTELS (только чтение) + сравнение
с PMS, которые используют наши рынки (Турция: Elektraweb, HotelRunner, Sedna/HMS; Россия: Bnovo,
TravelLine, Shelter, 1С:Отель; мир: Mews, Cloudbeds, Opera Cloud, SIHOT, Clock).

## Что видно сейчас

| | Состояние |
|---|---|
| Агентства | Сущность из одного поля `name`. API добавления есть (`POST /hotels/agencies`), **в интерфейсе его не вызывает ни одна страница** — агентство добавить негде. При первом открытии засеваются 7 жёстко прописанных (Anex, Coral, Pegas, TUI, Booking.com, …), среди них «Прямая продажа» — дублирует строку «Прямые продажи», которую аналитика рисует для броней без агентства. |
| Рынки / страны | Рынки заводятся на каждый отель вручную (код + название, в ATG по 4 на отель: TR, DE, «СНГ», UK). Справочника стран нет. В брони `market` — свободная строка без связи с рынком отеля, поэтому переименование рынка ломает аналитику по рынкам. |
| Гости | Гражданство — свободный текст. Аналитики по национальности гостей нет. Новое (сегодня): скан паспорта → ФИО/гражданство/номер/даты/пол. |
| Аналитика | KPI, pacing, воронка, типы номеров, рынки, агентства, демография гостей. **В ATG 0 броней** — проверить нечего; нужен способ наполнить данными. |
| Цены | Периоды, типы размещения с коэффициентами, цены по рынкам, стоп-продажи по датам, овербукинг. |
| Чего нет вообще | Контракты с агентствами, комиссия/нетто, квоты (allotment) и release, тип питания (RO/BB/HB/FB/AI/UAI), детская политика по возрастам, политика отмены, акции раннего бронирования / SPO, налог на проживание, выгрузка в полицию (KBS) / МВД, channel manager, ночной аудит. |

## Что есть у других PMS (кратко)

- **Турецкие (Elektraweb, Sedna, HMS)** — работают с туроператорами: контракт на сезон на каждое агентство,
  свои цены (нетто или с комиссией), тип питания, квота номеров с датой release, EB/SPO-акции, детская
  политика по возрастам. KBS-уведомление полиции/жандармерии (закон 1774) — либо встроено, либо через
  партнёра (Bulut KBS). Elektraweb — ~5800 отелей, PMS + booking engine + channel manager в одном.
- **HotelRunner** — сильнее всего как channel manager (сотни OTA), PMS проще.
- **Российские (Bnovo, TravelLine, Shelter, 1С:Отель)** — channel manager + booking engine + модуль
  регистрации иностранцев в МВД; агентства с комиссией.
- **Mews / Cloudbeds / Opera** — гостевой CRM, мультивалюта, revenue management, маркетплейс интеграций.

Наш модуль ближе всего к «контрактной» турецкой модели (рынки, нетто/брутто в брони), но без контрактов
и квот. Наше отличие, которого нет у них: CRM, ИИ-сотрудники, репутация/отзывы, WhatsApp — значит
догонять стоит только то, без чего отель не может работать, а не всю PMS.

## План

### Этап 0 — сразу (чтобы проверить аналитику)
1. **Справочник агентств в интерфейсе** (Отели → Агентства): добавить / изменить / удалить; поля —
   тип (туроператор / OTA / корпоративный / прямой), страна, комиссия %, контакт (имя, email, телефон),
   условия оплаты, заметка. Удаление — только если нет броней (иначе «в архив»).
   Убрать «Прямая продажа» из засева (дублирует «Прямые продажи»), засев только по кнопке «добавить типовые».
2. **Страны из справочника**: выбор рынка из списка стран ISO (с поиском, на ru/en/tr) + группы
   («СНГ», «Скандинавия»), вместо ручного ввода кода. В брони рынок выбирается из рынков отеля
   (хранить код, показывать название).
3. **Гражданство гостя из того же справочника стран** (скан паспорта уже отдаёт ISO-код) →
   аналитика «гости по странам».
4. **Демо-брони для проверки аналитики**: кнопка «Сгенерировать тестовые брони» (на выбранный отель,
   помечены как тестовые, удаляются одной кнопкой) — по агентствам, рынкам, датам, статусам.

### Этап 1 — контракты (ядро работы с туроператорами)
5. Контракт агентства на сезон: отели/типы номеров, нетто или % комиссии, тип питания, release (дней до
   заезда), квота номеров по датам, стоп-продажа по агентству.
6. Тип питания (RO/BB/HB/FB/AI/UAI) в ценах и в брони.
7. Детская политика: возрастные диапазоны (0–2, 2–6, 6–12), бесплатно / % от взрослого.
8. Политика отмены (бесплатно до N дней, штраф % / ночь) → видна в брони и фолио.
9. Аналитика: выручка и ADR по агентствам **нетто/брутто**, использование квот, release-календарь.

### Этап 2 — Турция / Россия
10. **KBS-выгрузка** (Турция): данные гостей (ФИО, гражданство, документ, дата рождения, пол — уже есть
    после скана) → файл/интеграция через партнёра (Bulut KBS или аналог). Для граждан Турции —
    TC Kimlik No (добавить поле).
11. **МВД (Россия)**: миграционный учёт иностранцев — через партнёра (Контур.ФМС и т.п.).
12. Налог на проживание (Турция, konaklama vergisi) в фолио.
13. Акции: раннее бронирование (EB, % до даты) и SPO (спецпредложения туроператору на период).

### Этап 3 — дистрибуция
14. Channel manager: не писать свой, а интегрироваться (HotelRunner / Elektraweb / TravelLine) —
    выгрузка доступности и цен, загрузка броней.
15. Ночной аудит: закрытие дня, начисления, отчёт смены.

## Статус (2026-10-25, вечер)

Ответы владельца: страна = страна туриста + страна покупки + страна агентства (все три влияют на рынки и аналитику);
нужны и комиссии, и нетто, и квоты с release, и блоки номеров, и добавление партнёров; страницы PMS — крупнее и нагляднее.

**Сделано и выложено (этапы 0 + 1):**
- Справочник стран ISO (`common/countries.ts`, `utils/countries.ts`, `CountrySelect`); рынок отеля = набор стран
  (миграция проставила страны всем 76 рынкам ATG); бронь сама относится к рынку по стране гостя.
- Бронь: страна гостя, страна покупки (по умолчанию — страна партнёра), контракт (авто по партнёру/отелю/дате/стране),
  блок, питание, дети, комиссия % → комиссия и нетто считаются сервером; скан паспорта подставляет страну гостя.
- Партнёры: страница списка (KPI, фильтры по типу/стране, архив), страница партнёра (профиль, контракты, блоки, брони,
  аналитика), «Добавить типовых»; засев туроператоров при первом открытии убран; удаление с бронями = архив.
- Контракты: страница-редактор — сезон, окно продаж, нетто/комиссия, питание (RO…UAI), release, гарантированная квота,
  продажа сверх квоты, мин. ночей, страны рынка, квоты и цены по типам номеров + квоты по датам и стоп-даты,
  политика отмены, детская политика, загрузка квоты по ночам, копирование.
- Блоки номеров (группы): предварительный/подтверждённый, дата отсечки, выкуп; подтверждённый блок держит номера.
- Проверка мест: блоки и гарантированные квоты держат номера, квота партнёра/стоп-даты/мин. ночей по контракту.
- Страница «Квоты и блоки»: шахматка свободно/продано/удержания по ночам с раскрытием по контрактам и блокам.
- Аналитика: период (раньше было зашито «последние 30 дней»), фильтры по трём странам и типу партнёра, KPI
  брутто/комиссия/нетто, «Рынки по странам» (гость/покупка/партнёр), партнёры с нетто/комиссией/ADR/отменами,
  демография гостей по реальным возрастам; кнопка тестовых броней (удаляются одной кнопкой).
- Список броней: валюта отеля вместо зашитого «$», страна, нетто, фильтр по стране.

**Сделано 2026-10-25 (вечер, этап 2 частично):**
- Журнал гостей `/hotels/guest-register` (KBS / МВД): заезды / в отеле / выезды на дату, проверка полноты по каждому
  гостю (имя-фамилия, гражданство, документ и срок, дата рождения, пол; для TR — T.C. Kimlik с контрольной суммой и
  имена родителей), выгрузка Excel с турецкими заголовками, отметка «передано» (guests[].kbsReportedAt).
  Прямой передачи в KBS нет — нужна авторизация разработчика в EGM.
- У гостя в брони: гражданство (справочник), для TR — TC Kimlik, имя отца/матери; скан паспорта ставит гражданство.
- Выписка партнёру (вкладка «Выписка»): по дате выезда/заезда, брутто/комиссия/нетто, PDF и Excel, отправка с почты отеля.
- В карточке брони убран зашитый «$», «Агентство» → «Партнёр».
- Цена в окне брони: блок → контракт (цена по типу номера) → рынок → прайс; ручная правка не перебивается.
- Акции контракта (миграция 1793800000000): раннее бронирование (бронь до даты), спецпредложение (период заезда),
  длительное проживание (от N ночей); суммируемые складываются, из остальных — лучшая. Сервер применяет при создании
  брони без явной скидки (сайт/импорт/API), окно брони — для новой брони с подписью «Акции контракта: …».

- Налоги отеля (миграция 1793900000000): налог на проживание % + НДС %, цены с налогами или без; налог на проживание
  входит в базу НДС (итог = база × (1+налог) × (1+НДС)); разбивка в карточке брони и в счёте; пресет «Турция 2% + KDV 10%».
  В счёте (folio PDF) убран зашитый «$» — валюта отеля.

- МВД (Россия): режим журнала гостей «МВД» (авто для отелей со страной Россия, переключатель вручную): поля уведомления
  о прибытии (место рождения, дата выдачи документа, миграционная карта — кроме граждан Беларуси, виза, цель въезда),
  срок подачи = следующий рабочий день после заезда (без учёта праздников), счётчик просроченных, Excel с русскими
  заголовками; доп. поля гостя в окне брони — только для иностранцев в российском отеле. Прямой подачи в МВД нет.

**Осталось (этап 3):** channel manager (через партнёра), ночной аудит.
