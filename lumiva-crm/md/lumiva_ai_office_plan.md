# ИИ-офис (ИИ-отделы) — план реализации

Источник дизайна: Claude Design project `3affa7c1-b28d-4e49-b8bb-c7af7123c758`
Страницы: `ai-office.html`, `ai-department.html`, `ai-department-edit.html`, `ai-office-connect.html`, `ai-office-plan.html`, `ai-brain.html`
Компоненты: `components/office-{data,map,shell,app,dept,edit,connect,plan,brain}.jsx`, `components/cabinet.jsx`; стили `styles/office.css`, `styles/office-pages.css`, `styles/cabinet.css`.

Принцип: никаких заглушек. Каждая цифра, статус, строка журнала и «реплика» на карте берётся из реальных данных.
Если в макете есть элемент, для которого нет источника данных, мы либо строим этот источник, либо убираем элемент. Демо-цифры не рисуем.

## Что есть в коде сейчас

| Нужно дизайну | Что есть | Разрыв |
|---|---|---|
| Отдел как сущность | нет; есть только `role` у `ai_agents` + жёсткие зоны (`ai-employee-role-catalog.ts`) | новая таблица `ai_departments`, агенты привязываются к отделу |
| Агенты отдела со своей ролью/промтом, руководитель ★ | `ai_agents` (роль из каталога, permissions, approval rules) | `department_id`, `is_lead`, `custom_title`, `dept_prompt`; роль `custom` с зоной = матрица прав отдела |
| Очередь задач backlog/progress/waiting/done с % и шагом | `ai_agent_actions` (pending/approved…), без прогресса и очереди | `ai_office_tasks` + исполнитель на BullMQ (уже есть в проекте, Redis) |
| Журнал действий (tool calls) | `ai_agent_logs` | писать каждый вызов инструмента с `department_id`, `tool`, результатом |
| «Нужна ваша помощь» (нет данных/доступа/ошибка) | нет | `ai_office_issues`; создаются агентом (инструмент `request_help`) и автоматически при 401/истёкшем токене; задача блокируется до решения |
| Мозг: папки, файлы, scope, индексация, «кто читал» | `ai_knowledge_items` (только текст, на всю компанию) | `ai_brain_files` + `ai_brain_chunks` + `ai_brain_reads`; извлечение текста md/txt/csv/xlsx(exceljs)/pdf/docx; поиск = Postgres FTS + эмбеддинги (`real[]`, cosine в Node; pgvector в `postgres:15` нет — образ БД не меняем) |
| Доступы (секреты по отделам) | `integration_connections` (креды интеграций) | scope «каким отделам» на подключение + статус/истечение; свои ключи — только для поддерживаемых коннекторов |
| Коннекторы | есть: CRM, почта, Telegram, WhatsApp, Meta Ads, Google Ads, Slack, Jira, Teams, HubSpot, amoCRM, Bitrix, Google Sheets/Calendar, Shopify… | нет: Notion, Canva, GitHub, МойСклад, Stripe (как данные клиента) — решение ниже |
| Движки | платформенные кредиты OpenAI + BYOK OpenAI/Anthropic | Claude Code Max-раннер и Codex — решение ниже |
| Расход за месяц по отделу | `ai_usage_log` (токены) | `department_id` в usage log, расход в € по прайсу модели |
| Тариф: 3 отдела в Enterprise, доп. слот 200 €/мес | тарифный биллинг Stripe/YooKassa/iyzico (ручное продление), plan rank enterprise=3 | слоты отделов в entitlements + покупка доп. слотов через существующие провайдеры |
| Автоматизации ↔ отделы | автоматизации → `handleAutomationEvent` ИИ-сотрудникам (в одну сторону) | действие «Задача ИИ-отделу» + триггеры от отделов |
| Живое обновление | нет WebSocket | polling лёгкого `/ai-office/live` раз в 3–4 с (без новой инфраструктуры) |

## Модель данных (этап 1)

- `ai_departments`: tenant_id, name, color, slot (x,y на карте), template_key, mission, system_prompt, rules (jsonb: набор флагов), permission_matrix (jsonb: 8 категорий × off/read/draft/appr/auto), connector_ids, engine (platform/byok:{provider,model}), monthly_budget_eur, parallel_limit, work_hours (24/7 | будни 9–19 | по запросу + tz), status (active/paused/budget_paused), kpi_keys (2 метрики для карточки), sort, created_by.
- `ai_agents` + department_id, is_lead, custom_title, dept_prompt.
- `ai_office_tasks`: department_id, agent_id, title, details, source (manual/automation/proactive/handoff/event/issue), source_ref, entity_type/entity_id, status (backlog/progress/waiting/done/rejected/failed/blocked), progress, step, plan (jsonb шагов), approval_payload, artifact (тип/ссылка/id), issue_id, priority, cost_eur, tokens, started_at/finished_at, created_by.
- `ai_office_issues`: department_id, agent_id, task_id, kind (error/data/access), title, detail, fix (upload/access/reconnect), target (folder/connector), status (open/resolved), resolved_by/at.
- `ai_brain_files`: folder ('common' | department_id), name, type, size, storage_path, body_md (для .md), scope (all | department_ids[]), index_status/progress, chunk_count, uploaded_by, updated_at. Учитывается в квоте хранилища тарифа.
- `ai_brain_chunks`: file_id, ord, text, tsv, embedding real[].
- `ai_brain_reads`: file_id, agent_id, task_id, read_at (для «Кто читает / последнее чтение»).
- `integration_connections` + department_scope (uuid[]), expires_at/health.
- `ai_usage_log` + department_id, task_id.
- Миграция данных: существующих ИИ-сотрудников раскладываем в отделы по их ролям, `ai_knowledge_items` переносим в «Мозг → Общее».

## Этапы

0. **Сверка дизайна с данными** — этот документ; согласовать с владельцем решения ниже.
1. **Бэкенд-ядро**: сущности, миграции, CRUD отделов/задач/проблем, RBAC (ключ `ai_office`), entitlements (слоты), перенос существующих данных.
2. **Движок исполнения (автономность)**: очередь BullMQ по отделам (лимит параллельности, рабочие часы, бюджет → пауза + уведомление). Диспетчер: руководитель отдела распределяет задачу на агента. Агент планирует шаги и выполняет их реальными инструментами (`ai-tools.service`), с учётом матрицы прав. Если уровень «С согласованием» — задача переходит в waiting, после одобрения продолжается. Есть передача задач между отделами (handoff), защита от зацикливания и дедупликация. Проактивный цикл: руководитель раз в N часов ставит задачи из цели отдела и KPI.
3. **Автоматизации ↔ отделы**:
   - действие «Поставить задачу ИИ-отделу» (шаблон с {полями}, привязка к сущности);
   - триггеры «Отдел: задача выполнена / отклонена / провалена / нужна помощь / бюджет исчерпан»;
   - маршрутизация событий CRM на отдел, а не на отдельного агента.
4. **Мозг**: загрузка файлов, извлечение текста, индексация с прогрессом, поиск по смыслу при каждой задаче, отметка о том, кто что читал. Агент записывает выводы в документы .md. Вкладка «Доступы» со scope по отделам.
5. **Фронтенд: Офис** — изометрическая карта и карточки из реальных данных, провода к подключениям, панель задач, одобрение задач, блок «Нужна ваша помощь», режим день/ночь. Реплики на карте — реальные события журнала, «прогулки» — реальные передачи задач.
6. **Фронтенд: Отдел и Редактор** — страница отдела (KPI, сотрудники, 3 колонки, живой журнал, пауза), редактор (все 7 секций и превью комнаты), шаблоны отделов.
7. **Подключения** — движки (кредиты/свой ключ, расход в реальном времени) и коннекторы (статус/истечение, какие отделы используют, переподключение через существующий OAuth).
8. **Тариф и оплата** — слоты, доп. отделы через Stripe/YooKassa/iyzico, курс ЦБ (рубли), расход API по отделам.
9. **Финал** — переводы ru/en/tr, пункты меню, проверка на одноразовом тестовом аккаунте, деплой, документация.

## Решения владельца (нужны до этапа 1/2)

1. **Движки Claude Code Max / Codex.** Это отдельный продукт: npm-раннер на машине клиента, который берёт задачи из CRM и запускает их в Claude Code/Codex под подпиской клиента. Есть риск по условиям провайдеров: потребительские подписки не предназначены для питания сторонних SaaS. Рекомендация: v1 — платформенные кредиты + свой API-ключ (Anthropic/OpenAI). Раннер — только после проверки условий, отдельным этапом.
2. **Новые коннекторы (Notion, Canva, GitHub, МойСклад, Stripe клиента).** Рекомендация: v1 — только существующие интеграции. Новые добавлять по одному под реальный спрос; первым МойСклад (рынок РФ). Canva требует одобрения приложения.
3. **Оплата доп. отделов.** Рекомендация: сразу картой через уже работающих провайдеров, а не «менеджер выставит счёт», как в макете.
4. **Доступ по тарифу.** В макете отделы доступны с Enterprise (3 включено, +200 €/мес за каждый). Подтвердить цифры и что делать с Ultimate.
