# Контент и публикации (SMM) — план

Начато 2026-11-06. Страница `/marketing/smm` + контент-отдел ИИ-офиса + SMM-сотрудник.

## Решения владельца (2026-11-06)
- Один движок публикаций с адаптерами под сети, без отдельного механизма на каждую сеть.
- Подключения создаются в «Интеграциях»/«Каналах», но все каналы сходятся в движок; отдел офиса и SMM-сотрудник пишут посты в движок.
- Режимы — как у ИИ-сотрудников, на уровне канала:
  - **Предложения** — ИИ только готовит текст и картинки (черновик), публикует человек.
  - **Помощник** — каждый пост ИИ уходит на согласование; после одобрения встаёт в расписание.
  - **Авто** — ИИ публикует сам всё, что входит в утверждённый контент-план.
- Ключ ИИ: платформенный (gpt-4o-mini, картинки — платформенная image-модель, списание квоты) или BYOK клиента (без списания).
- Первая сеть — Instagram. LinkedIn — и личный профиль, и страница компании; сначала настраиваем у себя (LUMIVA AGENCY) под личный профиль.

## Модель данных
- `content_channels` — канал публикации: сеть, аккаунт (страница / IG-бизнес / Telegram-канал / LinkedIn-профиль или компания / VK-группа), токен, режим, правила (часовой пояс, форматы, лимит постов в день), статус подключения.
- `content_plans` — контент-план (период, статус draft/review/approved, кто утвердил). В режиме «Авто» публикуется только то, что в утверждённом плане.
- `content_posts` — пост: заголовок, рубрика, формат (post / carousel / story / reel / article), текст, медиа (каждая картинка со своим статусом согласования), статус, источник (человек / ИИ-сотрудник / отдел офиса), комментарии.
- `content_variants` — пост × канал: свой текст под сеть, время, статус публикации, внешний id, ссылка, ошибка, попытки, метрики.

Статусы поста: `draft → review → changes → approved → scheduled → published | partial | failed`, `rejected`.
Статусы варианта: `pending → scheduled → publishing → published | failed | skipped`.

## Движок
- Cron раз в минуту: варианты `scheduled` с наступившим временем → адаптер → статус; до 3 попыток с паузой (5 / 15 / 60 мин), опоздание больше суток — `skipped`.
- Адаптер: `capabilities` (форматы, лимит символов, число картинок) → `validate(post, variant)` до публикации → `publish()` → `{ externalId, url }` → `metrics(externalId)`.
- Метрики — cron раз в час по постам за 30 дней.
- Картинки хранятся у нас (`uploads/content/<tenant>/…`, публичный URL) — Instagram и LinkedIn забирают картинку по ссылке; ссылки OpenAI живут час.
- Старая таблица `ai_office_posts` (Telegram-автопостинг офиса) — заменяется движком.

## Canva (план, 2026-11-06 — по просьбе владельца)

Идея: красивые картинки и карусели делаются в Canva, а в пост попадают без скачивания руками.

**Как будет работать для пользователя**
1. «Каналы → Canva → Подключить» — OAuth Canva Connect (у каждого клиента свой аккаунт Canva, мы ничего не храним, кроме токена).
2. В редакторе поста, блок «Картинки» — две кнопки:
   - **«Из Canva»** — список своих дизайнов (превью, поиск), выбрать дизайн → движок экспортирует его в PNG/JPG
     (многостраничный → каждая страница отдельной картинкой = карусель) и кладёт в пост как обычные картинки
     (дальше одобрение картинок и публикация — как сейчас).
   - **«Открыть в Canva»** — создать дизайн нужного размера (1080×1080 / 1080×1350 / 1080×1920 для сторис,
     LinkedIn 1200×627) с текущей картинкой поста или пустой, открыть редактор Canva; после «Готово» Canva возвращает
     пользователя обратно в пост (return navigation с correlation state), и движок сам экспортирует результат в пост.
3. ИИ-сотрудник/офис: в промпте картинки может выбрать «шаблон Canva» вместо генерации — автозаполнение
   брендового шаблона (заголовок, текст, фото) → экспорт → пост. Это даёт фирменный стиль вместо картинок DALL·E.

**API (Canva Connect)**
- OAuth 2.0 + PKCE, scope'ы примерно: `design:meta:read`, `design:content:read`, `design:content:write`, `asset:read`, `asset:write`, `profile:read`
  (+ `brandtemplate:meta:read`, `brandtemplate:content:read` для автозаполнения). Токен короткий, есть refresh.
- Список дизайнов `GET /v1/designs`; экспорт — задание `POST /v1/exports` (png/jpg, размер) → опрос `GET /v1/exports/{id}` → ссылки
  на файлы (временные — скачиваем к себе в uploads/content, как сейчас картинки ИИ); загрузка нашей картинки в Canva — `POST /v1/asset-uploads`;
  создание дизайна — `POST /v1/designs` (размер + ассет) → `edit_url`.
- Автозаполнение: `GET /v1/brand-templates` + `POST /v1/autofills` — **по нашим данным только для Canva Enterprise** (проверить на этапе сборки).
- Лимиты экспорта ~20–30 запросов/мин на пользователя — очередь экспорта с повтором.

**Что нужно от владельца**
- Создать интеграцию на canva.com/developers (Client ID/Secret → pl1 → OAuth-приложения → `canva`),
  redirect `https://crm.lumiva.agency/v1/content/canva/callback`, return navigation URL на `/marketing/smm`.
- Публичная интеграция (для всех клиентов) проходит ревью Canva; до ревью работает только для команды разработчика — нам для теста хватит.

**Этапы**: 1) подключение + «Из Canva» (выбор дизайна → экспорт в пост); 2) «Открыть в Canva» с возвратом; 3) автозаполнение
брендовых шаблонов для ИИ (если у клиента Enterprise). Статус: **все 3 этапа собраны 2026-11-06** (`content-canva.service.ts`, `CanvaPicker.tsx`), проверены на mock Canva API; живьём — после создания интеграции. Return navigation URL в настройках интеграции: `https://crm.lumiva.agency/v1/content/canva/return`.

## Этапы
1. Движок + модель + Каналы (Instagram, Facebook, Telegram, LinkedIn-профиль, LinkedIn-компания в коде) + Посты/Согласование/Контент-план/Обзор + режимы + ИИ-подготовка текста и картинок (платформа или BYOK) + контент-отдел офиса пишет в движок.
2. Аналитика постов (метрики IG/FB/Telegram-просмотры), VK, SMM-сотрудник с действием «подготовить пост», лучшее время публикации.
3. Видео/reels/сторис, TikTok, YouTube, Threads, A/B-тексты, повтор лучших постов.
